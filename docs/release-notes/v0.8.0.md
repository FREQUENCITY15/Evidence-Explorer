# Evidence Explorer 0.8.0 — public alpha

Evidence Explorer is a local audit surface for canonical AI agent-tool evidence. This first public alpha makes experiment records easier to inspect, validate, govern, and export without sending evidence to a hosted service.

## Highlights

- Canonical `schemaVersion: 1.0.0` validation with explicit completeness gaps and evidence references.
- Deterministic Govern classifications for experimental, host-internal, and forbidden tool use.
- Safe, line-addressable raw evidence rendering and malicious-content-safe UI behavior.
- Append-only JSON import, deterministic JSON and Markdown audit exports, and bounded checksum verification.
- A five-minute local walkthrough, public contribution and security guidance, issue templates, and automated tests on Python 3.12–3.14.

## Quick start

```bash
git clone https://github.com/FREQUENCITY15/Evidence-Explorer.git
cd Evidence-Explorer
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
uvicorn project_mentor.main:app --host 127.0.0.1 --port 8765
```

Open <http://127.0.0.1:8765/> and choose the bundled canonical sample.

## Trust boundaries

This is an evaluation build, not a production assurance product. It is designed for loopback-only use with synthetic or sanitized evidence. Do not expose the development server to a network or load secrets, credentials, personal data, or confidential production records.

Evidence Explorer validates structure and applies deterministic policy rules. It does not prove that submitted evidence is truthful, complete, or independently authentic. Raw-artifact checksums are verified only when the reviewer explicitly supplies the corresponding artifact.

## Known limitations

- Evidence storage is a bounded flat local directory, not a multi-user database.
- Authentication, authorization, remote deployment, and collaborative review are out of scope for this alpha.
- The canonical schema and governance vocabulary may evolve based on public compatibility reports.
- Checksum verification is ephemeral and does not persist uploaded raw artifacts.

Please report evidence compatibility problems through the repository issue template and security vulnerabilities through GitHub's private vulnerability reporting channel.
